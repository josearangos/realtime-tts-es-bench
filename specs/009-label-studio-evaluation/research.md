# Research: Label Studio Human Evaluation

## R1 — Label Studio image and version
- **Decision**: Build `evaluation/Dockerfile` as `ARG LS_VERSION` + `FROM heartexlabs/label-studio:${LS_VERSION}`, default read from `.env.example`. **Pinned to the latest stable release, `1.23.2`** (PyPI release 2026-09-29; Docker Hub tag `1.23.2` verified present 2026-11-04). The same version is used for the image and for any local development or tests that need Label Studio (e.g. `pip install label-studio==1.23.2` in a dev venv). The env variables and REST endpoints in [contracts/environment.md](contracts/environment.md) and [contracts/commands.md](contracts/commands.md) are still **to be verified against 1.23.2** at implementation. Daily `YYYYMMDD-…` tags and `develop` are rejected: they are CI builds, not releases. Upgrading the pin later is a deliberate change (see the upgrade edge case in the spec).
- **Rationale**: official image avoids installing from PyPI at run time (offline, FR-014); a thin Dockerfile gives one place to pin and later add files.
- **Alternatives**: `pip install label-studio` in a python base (slower, network at build, heavier); floating `latest` (breaks reproducibility).

## R1b — Open-source only (no paid features, no API keys)
- **Decision**: use only Label Studio Community Edition features: projects, label configs (`Audio`, `Rating`, `Choices`), local files serving, task import, user creation, random task sampling, JSON annotation export, all in the open-source image. The local token is generated by the instance itself and is not an external API key.
- **Avoided (Enterprise/paid)**: role-based access with per-project annotator assignment, task assignment/overlap automation, annotator performance dashboards, review workflows, SSO/SCIM, cloud audit logs. Substitutes here: quality metrics computed by our own `quality.py` from the export; all annotators see all projects (acceptable for a small trusted group).
- **Consequence**: with 2 to 5 annotators (confirmed), each completes whole projects by instruction; no enforced overlap and no batch-splitting is needed. To be checked when verifying 1.23.2.
- **No external services**: no cloud TTS/ASR, no LLM judges, no telemetry dependency; Label Studio telemetry is disabled via env (`LABEL_STUDIO_DISABLE_TELEMETRY`-style setting, name verified at implementation).

## R2 — Serving blind audio
- **Decision**: Label Studio *local files serving* with the document root mounted read-only from `output/evaluation/served/`; tasks reference `/data/local-files/?d=<item_id>.wav`. Files are named only by opaque id.
- **Rationale**: no upload copies, filenames are opaque, nothing about engines leaves the private mapping. Removing a voice = delete files + tasks.
- **Alternatives**: uploading media into LS (duplicates data into the volume and into backups, harder to purge); external storage/S3 (network, overkill).

## R3 — Project layout for MOS
- **Decision**: one MOS project, three `Rating` controls (naturalness, pronunciation, prosody) per audio; separate CMOS and SIM projects.
- **Rationale**: same sentence and listen for all three criteria, 3× fewer listens. Risk: halo effect between criteria; mitigated by distinct anchors per criterion and documented in the report.
- **Alternatives**: three separate MOS projects (cleaner independence, 3× annotation effort). Easy to switch because `labelconfig.py` generates configs from criteria list.

## R4 — Scales (frozen before collection)
- **Decision**: MOS and SIM use 5-point absolute category ratings with Spanish anchors; CMOS uses 7-point −3…+3 comparison of B against A. Full text in [contracts/labeling-interfaces.md](contracts/labeling-interfaces.md). A SHA-256 over the scale definitions is stored in `batch.json` and in every export row; a mismatch with the live project config blocks provisioning.
- **Alternatives**: continuous sliders (harder to anchor), MUSHRA (needs hidden reference and more listens).

## R5 — Blind mapping and randomization
- **Decision**: `random.Random(seed)` drives item selection, order and A/B swap; opaque id = 12 hex chars from `secrets`-style generation seeded by the same RNG (reproducible for a seed, not guessable from names). Task order is also randomized in LS using "random ordering" project setting. Mapping stored as JSONL in `output/evaluation/private/` (not mounted).
- **Rationale**: reproducible re-prepare for tests; annotators cannot infer engine from ids or order.

## R6 — Quality control
- **Decision**: repeats (default 10%) measure intra-annotator consistency (mean absolute difference, share within ±1). Attention checks (default 5%): instructed-response over a generated tone, and degraded anchor (noise at 0 dB SNR, expected ≤ 2 on every MOS criterion). `quality` reports per annotator: repeat consistency, failed checks, count, flagged if below thresholds in `batch.toml`. Flags inform exclusion; **exclusion is a documented analysis step, not automatic deletion** (raw annotations stay).

## R7 — Loudness
- **Decision**: numpy RMS normalization to −23 dBFS with −1 dBFS peak limit, applied identically to every staged clip; originals untouched; settings recorded in `batch.json`. Reference recordings in SIM are normalized the same way.
- **Alternatives**: ITU-R BS.1770 LUFS (needs a dependency such as pyloudnorm/ffmpeg; RMS is adequate for short speech and keeps the provisioner dependency-free). Documented as a limitation.

## R8 — Provisioning flow and idempotency
- **Decision**: one-shot `provisioner` service `depends_on: label-studio: condition: service_healthy`; runs `prepare` then `provision`. Project key = title; task key = `data.item_id`. LS import called only with missing tasks. Re-running `prepare` reuses `batch.json`.
- **Rationale**: matches FR-004/013; restart of the stack re-runs it safely.

## R9 — Persistence, backup, restore, reset
- **Decision**: named volume `ls-data` for DB and media. `eval-backup`: stop LS (SQLite consistency), tar the volume and `output/evaluation/` (served + private + batch.json) into `backups/evaluation/<timestamp>.tar.gz`, restart. `eval-restore <file>`: requires LS stopped and empty/confirmed volume, extracts, starts. `eval-reset`: asks for typed confirmation (`RESET`), removes volume and `output/evaluation/`. Verification of SC-003: export before and after restore, byte-compare annotation columns.
- **Alternatives**: LS JSON export as backup (loses user accounts and project settings); Postgres (extra service, not needed at this scale).

## R10 — Network and credentials
- **Decision**: `ports: "${LS_BIND:-127.0.0.1}:${LS_PORT:-8080}:8080"`; sign-up disabled; admin username/password/token from `.env` (gitignored; `.env.example` has placeholders). Preflight refuses `change-me` passwords when `LS_BIND` is not loopback.
- Security warning for LAN exposure printed by `eval-up` and in the README (plain HTTP; use a trusted network or reverse proxy with TLS).

## R11 — Pseudonymous annotators
- **Decision**: `eval-annotator ID=a03` creates an LS user with email `a03@eval.invalid`, no names, generated password printed once. Export contains only `annotator_id` (`a03`), never the email.

## R12 — Source audio discovery
- **Decision**: `sources.py` reads existing synthesized WAVs and their sidecar/metadata from the layout produced by earlier features (`output/speaker/*`, `output/intelligibility/*`) plus a generic `--source-manifest` JSONL (`engine, voice, accent, sentence_id, wav`) for anything else. Items are matched on sentence id across engines so all conditions share sentences.
- **Open at implementation**: confirm the exact on-disk sidecar fields of 004/005/006 outputs; the manifest route removes the dependency.

## R13 — Offline operation
- **Decision**: no image pulls at `up` (`pull_policy: never` for the built image once present; `eval-up` uses `docker compose up -d --build` only when the image is missing), no CDN assets (Label Studio ships its UI), provisioner uses no network beyond the compose network.
